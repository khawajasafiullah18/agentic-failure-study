# Evidence map — which script produces which result

Every number in the report traces to a script in this folder and a file in `06_tables/` or
`07_figures/`. Nothing is typed by hand. This page is the index for that chain.

Reproduce everything with the commands in the next section, then compare against
`SHA256SUMS.txt` at the package root.

## Commands

```
pip install -r requirements.lock.txt    # exact versions; requirements.txt is the loose set
set PYTHONPATH=src          # bash: export PYTHONPATH=src

python -m afs.cli build      # raw issues -> processed corpus (applies the codebook)
python -m afs.cli analyze    # all ten RQ tables + analysis_results.json
python -m afs.cli validate   # E1-E5 instrument suite and F1-F4 findings suite
python -m afs.cli requirements   # 26-row traceability matrix
python -m afs.cli export     # report, paper, deck, one-pager, coder packet
python -m afs.cli aidev      # AIDev second corpus
python -m afs.cli score-coder    # Cohen's kappa once the 40-row sheet is filled
```

Every table is regenerated by one command. Verified on 10 November 2026 by extracting
`11_code/` alone into an empty folder and running the pipeline there:

- `afs.cli analyze` reproduced all ten RQ tables **byte-identically** (SHA-256 compared
  before and after).
- `afs.cli validate` reproduced the validation numbers: perturbation retention 0.8133,
  ablation change rate 0.0265, findings verdicts 2 stable / 2 direction-stable / 1 not
  stable, complexity tiers 699 / 1,258 / 921 / 211, 49 exemplars.

`11_code/` carries its own copy of the corpus (`data/processed/`) and the reference
annotation (`data/gold/`), so these commands run without the application.

## Labeller and codebook

| Artefact | File | Notes |
|---|---|---|
| Rule-based labeller | `src/afs/classify.py` | `FailureLabeller`: lexicons weighted 3.0/2.0/1.0, exception rules, four precedence rules |
| Codebook source | `configs/taxonomy.v1.yaml` | 5 dimensions, 37 codes, each with definition/include/exclude |
| Codebook validator | `src/afs/taxonomy.py` | `validate()` fails the build if a code is incomplete |
| Corpus builder | `src/afs/dataset.py` | raw GitHub JSON → labelled records |
| Collector | `src/afs/collect.py` | issue-tracker pull |
| Source registry | `src/afs/sources.py` | the 8 repositories and their counts |
| AIDev processor | `src/afs/aidev.py` | `build()` over `hao-li/AIDev` parquet tables |
| Exemplars | `src/afs/exemplars.py` | 49 cited examples, 10/10 categories |

The labeller is deterministic and rule-based rather than LLM-based on purpose: an LLM
labeller would make every number depend on a model version, and the corpus would stop being
reproducible from the shipped data.

## Known gaps

1. **No notebooks.** The analysis is a Python package with a CLI, not a set of notebooks.
   `python -m afs.cli analyze` is the equivalent of "Run all", and it writes the tables
   directly. Nothing is done by hand in a cell.
2. **The CrewAI/AutoGen pilot is not in this package.** It is prior work, described in
   report section 9.6 with its two tasks, pinned commits and frozen regression test. It was
   deliberately not re-run or folded in: two repair tasks cannot estimate a prevalence over
   3,089 failures, which is what RQ1-RQ3 report.
3. **The public repository mirrors the application and the engine, not the full pipeline.**
   `11_code/` here is complete, so the validation suite is reproducible from this package
   even where the repository is thinner. The same folder is staged as `pipeline/` in the
   repository.
